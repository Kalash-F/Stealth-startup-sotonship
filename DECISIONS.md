# DECISIONS

Deviations from `plan.md`, contract interpretations, and assumptions. Newest at the bottom.

## Phase 0

- **D0.1 Repo layout: no `tbml-checker/` wrapper.** plan §3.2 shows everything under `tbml-checker/`. The repo root *is* that folder, so `backend/`, `data/`, `web/`, `reports/` sit at the repo root.
- **D0.2 Backend is an installable package.** `backend/pyproject.toml` defines package `tbml`; `make setup` creates `.venv/` and runs `pip install -e "backend[dev]"`, so `from tbml.pipeline import check` works from anywhere with the venv active. `tbml/paths.py` assumes an editable install (it resolves `data/` relative to the source tree).
- **D0.3 Python version.** plan says 3.11+. Developed and tested on 3.13; `requires-python = ">=3.11"`.
- **D0.4 Rule enum source.** plan §4.6 says the `rule` enum is "see §7.2", but there is no §7.2; the rules are R1–R8 in Phase 4 §4.2. `Rule` enum = `PRICE_OUTLIER, QTY_VALUE_IMPLAUSIBLE, PLACEHOLDER_DESC, GEO_INCONSISTENT, ROUTE_NO_ECONOMIC_SENSE, ARITHMETIC_ERROR, RESIDENTIAL_CONSIGNEE, LOW_CONFIDENCE`.
- **D0.5 `Report.lines` shape.** plan §4.7 says `list[{LineItem + EnrichedLine + Benchmark | null}]`. Implemented as `ReportLine`: every `LineItem` field and every `EnrichedLine` field flattened into one object (they share `line_id`), plus `benchmark: Benchmark | null`. Frontend code should read e.g. `report.lines[0].unit_price`, `report.lines[0].hs6`, `report.lines[0].benchmark?.p90`.
- **D0.6 `hs6_candidates` item shape.** `{hs6: str, score: float 0–1}` as model `HS6Candidate`; at most 3 entries ("top 3").
- **D0.7 Nullable means required-but-nullable.** Every field typed `X | null` in §4 must be present in the JSON; its value may be `null`. No field has a default. This is the strictest reading and makes "missing field" tests meaningful.
- **D0.8 Validation added beyond §4 types** (all derived from the §4 notes column): unknown fields rejected (`extra="forbid"`); `country` = 2 upper-case letters; `currency` = 3 upper-case letters; `hs6` = 6 digits; `line_id` = `L<n>`; `Benchmark.route` = `XX-XX` or null; confidences 0–1; `priority_score` 0–100; `n_observations`, `processing_ms` ≥ 0; `Benchmark` bands must satisfy p10 ≤ p25 ≤ median ≤ p75 ≤ p90 (the Phase 3 monotonic requirement, enforced at the contract so a bad band can never be loaded).
- **D0.9 Fixtures are mock.** The benchmark fixture has `is_mock: true` and `sources: ["mock (test fixture)"]`; the invoice fixture has `is_synthetic: true` and company names suffixed "(synthetic)".
- **D0.10 Stub API.** `api.py` already serves `GET /health` and a stub `POST /check` (returns the fixture report) with CORS for the Vite dev server, so frontend work can start before Phase 5. Full Phase 5 endpoints/error handling are not built.
- **D0.11 Extra dependencies declared up front.** `pandas` and `pyarrow` (Phase 3 parquet bands) are in `backend/pyproject.toml` now, so parallel threads don't have to edit the same dependency list.

## Phase 1

- **D1.1 Generator code lives in the package.** Logic is in `backend/tbml/synthetic/` (`catalogue.py`, `generator.py`, `render.py`, `templates/`); `backend/scripts/generate_invoices.py` is a thin CLI. This lets tests import the generator without path hacks.
- **D1.2 Placeholder bands.** Phase 3 bands don't exist yet, so clean prices are sampled from `data/reference/placeholder_bands.json`: approximate global bands, `is_mock: true`, `n_observations: 0`, source "placeholder (approximate, not real trade data)". Units: kg for 731815/090111/740311, l for 220210, u for 852351/610910/847130. When Phase 3 lands, regenerate with `--bands data/benchmarks/bands.parquet` and change `DEFAULT_BANDS` in `generator.py` so `test_committed_dataset_matches_generator` keeps passing. If real bands use a different unit for an HS6, update `bench_per_unit` in `catalogue.py` too.
- **D1.3 FX table.** `data/reference/fx.csv` holds rounded, approximate 2024 annual averages (AED is the USD peg). Rows other than USD/AED say "verify in Phase 3"; the Phase 3 owner should replace them with a cited source.
- **D1.4 Extra ground-truth files.** The `Invoice` contract has no HS6 or USD price, but Phase 3 tests need them. Besides `truth/{id}.json` (pure `Invoice`) and `labels.csv`, the generator writes `lines.csv` (per line: expected `hs6` (empty for placeholder lines), `true_hs6`, `benchmark_unit`, `bench_units_per_unit`, `normalised_quantity`, `unit_price_usd`, `fx_units_per_usd`, `label`) and `invoices.csv` (per invoice: `role` clean/anomalous/hard_negative, labels, template, route, currency).
- **D1.5 `labels.csv` shape.** Columns `invoice_id,line_id,label,hard_negative,detail`. One row per planted anomaly (`line_id` empty for invoice-level anomalies: GEO, RESIDENTIAL, ARITHMETIC sum errors). Hard negatives have no anomaly, so each gets one row with `label` empty, `hard_negative = CLEAN_HARD`, `detail` = kind. Invoices with no row are plain clean.
- **D1.6 Mix.** n=60 → 18 anomalous (30%), 6 hard negative (10%), 36 clean. Each anomaly type appears exactly 4 times at n=60 (14 invoices carry 2 anomalies, 4 carry 1, pairings shuffled and never the same type twice). The 4-per-type target scales up for larger n.
- **D1.7 How anomalies are planted** (thresholds chosen to clear the Phase 4 rule thresholds with margin):
  - `OVER_PRICE` ×3–×1000 median (log-uniform); `UNDER_PRICE` ÷3–÷100 median. Price lines avoid the parity commodities so they don't also look like route anomalies.
  - `QTY_VALUE_IMPLAUSIBLE`: 1–20 printed units with a line total of ~USD 150k–2M, and always ≥ 15× p90 per benchmark unit (R2 ceiling is 10× p90). These lines are necessarily also extreme price outliers, as in the plan's own example.
  - `ROUTE_NO_ECONOMIC_SENSE`: a parity commodity (copper cathodes 740311 or green coffee 090111, exchange-traded so prices are near identical across countries) priced between p75 and p90. **Assumption to re-check in Phase 3** against per-route medians (R5 needs origin/destination medians within ±15%).
  - `ARITHMETIC_ERROR`: half line-level (line total off by max(3–40%, 10 units)), half invoice-level (stated total off by max(3–25%, 10 units)); always beyond R6's 0.5% / 1-unit tolerance. Every other invoice is exact to the cent.
  - `GEO_INCONSISTENT`: half "city of country A, country B" origin text (e.g. "Plzeň, United Kingdom"), half an unexplained third-country origin vs a loading port in the seller's country.
  - `RESIDENTIAL_CONSIGNEE`: consignee is a named private person at a flat/apartment in the buyer country; invoice total ≥ USD 30k.
  - `PLACEHOLDER_DESC`: description replaced by e.g. "Product ABC", "Goods as per contract", "Item 1"; price stays clean; `lines.csv` expects `hs6` = null.
- **D1.8 Explained re-exports are clean.** Real Dubai and coffee trade involves re-exports, so some clean invoices have a third-country origin *with an explanation in the origin text*, e.g. "China (re-exported from Jebel Ali Free Zone, Dubai)". The GEO rule (R4) must treat origin text containing "re-export" or "transhipped" as explained. Without such a phrase, origin ≠ seller country is the planted anomaly.
- **D1.9 Hard negatives** (`CLEAN_HARD`), cycling three kinds: `premium_near_p90` (one non-parity line at 75–95% of the way from p75 to p90 on a log scale, described as Premium/Branded), `bulk_discount_near_p10` (one line between p10 and p25, 1.5–3× the usual top quantity, "bulk order, volume discount applied"), `unusual_route_explained` (third-country origin transhipped through Felixstowe or re-exported from Jebel Ali, stated on the invoice). All stay within p10–p90.
- **D1.10 Templates.** `classic` (serif, "Quantity / Unit / Unit Price / Amount", date "14 March 2024"), `modern` (sans, "Qty / UoM / Rate / Total", "Bill to/Ship to", ISO date), `trade` (monospace boxed form, "Description of Goods / Quantity (with unit) / Unit Price / Value", DD/MM/YYYY, descriptions in upper case). Phase 2 string comparison must be case-insensitive (plan: "normalised equality"). Every page carries a "SYNTHETIC TEST DOCUMENT" footer; truth JSON has `is_synthetic: true`.
- **D1.11 Printed precision.** Unit prices print with 2 dp (≥ 10), 4 dp (≥ 0.01) or 6 dp (< 0.01, needed for heavily under-priced screws); truth stores exactly what is printed.
- **D1.12 Fictional parties.** Company names, street names and postcodes are invented from word lists; city and port names are real so geography checks have something to work with. UK postcodes use the right area for the city but invented districts/units.
- **D1.13 PDFs are not byte-identical across runs** (WeasyPrint embeds a timestamp). The plan's reproducibility check is on truth JSON and `labels.csv`, which are byte-identical; `lines.csv` and `invoices.csv` are too.

## Phase 3B/3C (classification and normalisation)

- **D3.1 Repair of main after the 3A merge.** `data/reference/fx.csv` held two tables with different headers (3A annual `year,currency,usd_per_unit` and Phase 1 `currency,units_per_usd`), which broke the generator and its tests. Split: `fx.csv` is the Phase 1 table again (one 2024 rate per currency, used by the generator and by normalisation); 3A's table moved to `fx_annual.csv` and `fetch_benchmarks.py` reads that. Also declared `requests` (imported by `fetch_benchmarks.py`) in `pyproject.toml`, ran `ruff format`, and exempted `scripts/fetch_benchmarks.py` and `tests/test_benchmark.py` from E501.
- **D3.2 `hs6.csv` is partial and unverified.** The sandbox cannot reach HMRC or WCO (403), so `data/reference/hs6.csv` has the 7 §5.1 codes plus ~24 sibling and unrelated codes (needed so validation can reject wrong guesses) written from recall of HS 2022. Replace it with the official list when a machine with access is available; the `keywords`/`exclude` columns drive only the offline baseline and can stay as they are. Descriptions are shortened official wording.
- **D3.3 Classification reason lives in `normalisation_note`.** `EnrichedLine` has no reason field and the schema is frozen. When `hs6` is null the note starts `not classified: <reason>;`. Schema unchanged.
- **D3.4 Proposers.** `AnthropicProposer` (temperature 0, JSON reply, one retry with the error, model from `LLM_MODEL`) wrapped in `CachedProposer` (disk cache `data/cache/classify/`, key = model + prompt version + lower-cased whitespace-collapsed description). `default_proposer()` uses it only when both `ANTHROPIC_API_KEY` and `LLM_MODEL` are set; otherwise the deterministic `KeywordProposer` (score `1 - 0.4**hits`). The LLM path is tested with a fake client only; it has not been run against the live API. The cache directory is not gitignored, so cached answers can be committed for the offline demo (plan 9.2).
- **D3.5 Thresholds.** Top score `< 0.5` gives null (exactly 0.5 is accepted). Placeholder lines are detected before any proposer call, get `hs6 = null`, confidence `0.05`. A placeholder is a description whose words are all generic filler, so "Bolts as per contract" is not one.
- **D3.6 Normalisation never guesses.** A pieces to kg conversion needs a matching row in `unit_weights.csv` (matched on a word in the description, e.g. `m6`); pieces to litres needs a volume in the description; cartons need "carton of N". Anything else gives null quantity and price with the reason in the note. Pack sizes stated in the description override table defaults. The M4 weight (0.003 kg) is rounded up from a ~2 g estimate to agree with the generator's catalogue; review before production.
- **D3.7 FX.** One 2024 rate per currency, whatever the invoice date (per-date adjustment is in the §12 backlog). Rates are still the approximate ones from D1.3.
- **D3.8 Benchmark unit source.** Units come from `bands.parquet` if present, else `bands_mock.parquet`, so they cannot drift from the bands.
- **D3.9 Tests never call the LLM.** `tests/conftest.py` removes `ANTHROPIC_API_KEY` for every test.

## Phase 5 (pipeline + API)

- **D5.1 Lint repair on main.** `make lint` failed on main with 32 E501 (long docstrings and reason strings) after the parallel merges. Ignored E501 for `tbml/**` in `pyproject.toml` rather than hand-wrapping user-facing strings; `ruff format` is still enforced.
- **D5.2 Benchmark lookup was still the Phase 0 stub.** `tbml/benchmark` now reads `bands.parquet` else `bands_mock.parquet`, returns the route row (`ORIGIN-DEST`, seller country to consignee/buyer country, same as R5) if present, else the global row. `benchmark(line, route=None)` gained the optional `route`. `benchmarks_are_mock()` drives `/health`.
- **D5.3 Mock bands differ from the generator's placeholder bands** (e.g. 852351 median 10.5 vs 4.5). End to end over the 60 synthetic PDFs all 36 clean and 6 hard-negative invoices are `low`; 17 of 18 anomalous are not `low`. The miss is INV-2024-0009 (ROUTE_NO_ECONOMIC_SENSE): its price sits between p75 and p90 of the placeholder band but not above the mock p75. Fixed by regenerating with real bands (see Phase 1 note).
- **D5.4 `USE_MOCKS=1`** swaps extraction and benchmarking for the fixtures (`tbml/stubs.py`); classification, rules and scoring stay real. `/health` then reports `stubs: true`.
- **D5.5 Rule skip warnings** from `run_rules_with_warnings` are appended to `Report.warnings` (deduplicated).
- **D5.6 Errors.** Anything not starting with `%PDF` gives 400; a PDF the parser cannot open gives 400 ("could not be read"); a valid PDF with no text layer gives 200 with warnings and a minimal invoice (extraction's own behaviour); more than 10 MB gives 413 (the body is read in one go, capped at 10 MB + 1 byte). Unexpected exceptions are the only 500s.
- **D5.7 Report cache.** `data/reports/{invoice_id}.json` (gitignored; `TBML_REPORTS_DIR` overrides). Ids are sanitised to `[A-Za-z0-9._-]` for the filename, so two ids that differ only in other characters collide. A later check of the same id overwrites.
- **D5.8 Extra endpoint.** `POST /samples/{invoice_id}/check` runs a bundled sample without a file upload (for the demo). `GET /samples` includes the planted labels, since the samples are synthetic.
- **D5.9 Timing.** Stage timings are logged at INFO (`tbml.pipeline`). Median over the 60 synthetic PDFs on the offline path: 0.08 s per invoice (the LLM path was not run: no API key here).

## Hierarchical classifier

- **D7.1 Three-step classification.** `tbml/classify/hierarchical.py`: the LLM picks the chapter (2 digits), then a heading (4) from the real headings under that chapter, then the HS6 from the real subheadings under that heading. It can never invent a code. A step whose best score is below 0.5 stops the walk ("not sure"), so the line gets `hs6=None` and the price check is skipped with a warning. Final confidence = the weakest step on the path. Each step is cached in `data/cache/classify_hier/`.
- **D7.2 Default LLM path.** With `ANTHROPIC_API_KEY` and `LLM_MODEL` set, `default_proposer()` now returns the hierarchical proposer. `CLASSIFIER=flat` restores the old one-call proposer, `CLASSIFIER=keyword` forces the offline baseline (for evaluation).
- **D7.3 Nomenclature file.** Any CSV with a code column and a description column (`tbml/classify/nomenclature.py`). Dots and spaces in codes are stripped, chapters 1-9 get their leading zero back, 8/10-digit national lines fold into HS6, and missing chapter/heading rows are derived ("Chapter 84") so the tree is always complete. Looked up at `HS_NOMENCLATURE`, else `data/reference/hs_nomenclature.csv`, else the partial `hs6.csv`. Until the full list lands, the derived chapter/heading descriptions are bare numbers, which will hurt accuracy.
- **D7.4 Validation list.** `default_hs6()` now also accepts every six-digit code of the nomenclature (without keywords, so the keyword baseline is unchanged). Codes without a price band are skipped by the price rules, as before.
- **D7.5 Explanation.** The path ("84 ... (0.97) > 8471 ... (0.95) > 847130 ... (0.92)") is prepended to `normalisation_note` as `HS path: ...`; when the walk stops, its reason becomes the "not classified" reason. Schema unchanged.
- **D7.6 OpenRouter as the LLM provider.** All LLM calls (extraction, flat and hierarchical classification, and future features) go through `tbml/llm.py`. `configured_client()` returns an OpenRouter client when `OPENROUTER_API_KEY` and `OPENROUTER_MODEL` (or `LLM_MODEL`) are set, else the Anthropic client when `ANTHROPIC_API_KEY` and `LLM_MODEL` are set, else None (offline paths). OpenRouter is called with plain `requests` against its OpenAI-compatible chat-completions endpoint, temperature 0, retries on 429/5xx and network errors (2 retries), no retry on 4xx. Both clients expose `complete()` and an Anthropic-style `messages.create()` shim, so the classifiers did not change shape. Provider failures raise `LLMError`, which the classifiers turn into `ProposerError`, so an outage gives "classifier unavailable" lines, never a crash. `/health` reports `llm: openrouter:<model>` or `offline`. `AnthropicProposer` is renamed `LLMProposer` (old name kept as an alias). Tests set `TBML_NO_DOTENV=1` so a real `.env` can never put a key into the test run.
- **D7.7 Full HS list.** The classifier now reads Ali's `hs.db` (repo root; built by `backend/scripts/load_hs_json.py` from `HS.json`, the UN Comtrade "Combined HS" reference list): 98 chapters, 1,266 headings, 6,897 HS6 codes, all seven target goods present with official descriptions. Lookup order: `HS_NOMENCLATURE`, `hs.db`, `data/reference/hs_nomenclature.csv`, `hs6.csv`. Chapters 99 (Comtrade's catch-all "Commodities not specified according to kind", 999999) and 77 (reserved) are excluded so the model cannot file goods under "not specified". `hs6.csv` stays as the keyword baseline's list. `hs.db` lives at `data/reference/hs.db` (moved from the repo root so the Vercel build, which copies `data/` into the backend bundle, ships it); a repo-root `hs.db` is still read as a fallback.
- **D7.8 OpenRouter without `requests`.** `tbml/llm.py` calls OpenRouter with `urllib` from the standard library, because the Vercel deploy fix (branch `claude/admiring-mayer-lydv9e`) drops `requests` from the deployed dependencies. Network failures are caught as `OSError`. A test runs the real urllib path against a local HTTP server.
## Deployment (Vercel)

- **DV1 Bands are JSON, and offline-only libraries are an extra.** The first Vercel deploy failed with `LAMBDA_SIZE_EXCEEDED`: the backend bundle was 325 MB against a 225 MB cap, almost all of it pyarrow, pandas and numpy, which the API used only to read the 7 KB `bands_mock.parquet`. Bands are now `data/benchmarks/bands.json` / `bands_mock.json` (a JSON list of `Benchmark` rows, the same shape as `placeholder_bands.json`), read with the standard library by `tbml.benchmark.band_table()`, which `normalise.benchmark_units()` also uses. This deviates from plan 3.4/3.5, which name `.parquet`. `fetch_benchmarks.py` writes the JSON. `pandas`, `requests`, `jinja2` and `weasyprint` moved to the `scripts` extra (`dev` includes it, so `make setup` is unchanged); `pyarrow` is gone. The backend bundle is now about 81 MB.
- **DV2 Data ships inside the backend bundle.** Vercel bundles the `backend` service from `backend/` only, so `data/` was missing at runtime. The service's `buildCommand` copies `../data` to `backend/data/` (gitignored), and `tbml/paths.py` uses `backend/data/` when `<repo>/data/` does not exist. Locally nothing changes.
- **DV3 Writable state goes to the temp dir when `data/` is read-only.** Vercel mounts the code read-only. When `data/` is not writable, `tbml/asgi.py` defaults `TBML_CACHE_DIR` and `TBML_REPORTS_DIR` to `<tmp>/tbml/` (explicit settings still win). The classification cache now honours `TBML_CACHE_DIR` too (`paths.cache_dir()`). These caches are per instance and lost on a cold start, so `GET /api/reports/{id}` can 404 for a report made on another instance; durable storage is out of scope for the demo.
- **D7.9 Merged main (Vercel deploy fix, PR #16).** Import conflicts in proposers.py and extract/llm.py resolved by keeping both sides (LLMError from tbml.llm, cache_dir from tbml.paths). The hierarchical cache now resolves `tbml.paths.cache_dir()/classify_hier` when the proposer is built, so asgi.py's temp-dir redirect applies on Vercel, and a failed cache write is ignored rather than failing classification. Checked in a venv with only the deployed dependencies (no requests/pandas/pyarrow) on a copy of the Vercel bundle layout: hs.db found under data/reference, OpenRouter selected from env, MacBook classified 84 > 8471 > 847130. Path text in notes is cut to 60 characters per level.

## Evaluation and checker (Phase 6 / 7)

- **D8.1 Evaluation.** `backend/scripts/evaluate.py` (`make eval`) writes `reports/eval/summary.{json,md}`. Part A scores keyword vs flat LLM vs three-step LLM on `data/eval/descriptions.csv` (44 lines of realistic wording: jargon, brand names, near-miss goods, vague filler; true codes checked against `hs.db`). Part B runs the full pipeline from PDF on the 60 synthetic invoices: invoice P/R/F1, recall per planted type, hard-negative false positives, and the review-budget comparison against 10,000 random spot-checks. The LLM provider is probed once; if unreachable only cached answers are used and the summary says so. No PNG chart (matplotlib not installed): the table is the slide. Held-out seed (plan 6.4) not done yet.
- **D8.2 Checker page.** `/app/checker` in the workspace shell (not the reserved top-level `/checker`) so it shares the sidebar; nav item "Check invoice". `web/src/lib/api.ts` is the typed client; all calls go to same-origin `/api/*` (vercel.json routes them to the backend). In `next dev`, `next.config.ts` rewrites `/api/*` to `API_PROXY_TARGET` (default `http://127.0.0.1:8000`, i.e. `make api`); the rewrite is off in production builds. The page shows the classifier in use (`/health` llm) and a mock-prices badge, the priority, flags, each line's HS code, AI path and price band, and the report's warnings as "What was not checked".
- **D8.3 Live classification results and model choice.** First live run (gpt-4o-mini, no interpretation step): 3-step 23/39, below the keyword baseline's 26/39, 14 confidently wrong; the flat proposer failed on 35 lines because the model wrote codes as "8471.30" / 4 digits. Fixes: parsers keep only the digits (and restore a dropped leading zero), the flat parser skips 4-digit codes instead of rejecting the whole reply, and the hierarchical proposer has a step 0 that asks the model what the goods are in plain words (or whether the line is too vague) and feeds that reading into every step (`interpret=True`, PROMPT_VERSION 2). Comparing models on OpenRouter with the fixes: gpt-4o-mini 3-step 28/39, claude-haiku-4.5 30/39, gemini-2.5-flash 37/39 to 39/39 across runs, with 0 to 1 confidently wrong and 5/5 vague lines left unclassified. Default model: `google/gemini-2.5-flash`. Results vary slightly run to run even at temperature 0, so the pitch should quote the range (95-100%), and the committed cache (`data/cache/classify*`) makes `make eval` and the demo reproduce the committed numbers offline.

## Real data (Phase 3 completion)

- **D9.1 Real bands from committed HMRC data.** `fetch_benchmarks.py --from-raw` rebuilds `data/benchmarks/bands.json` with no network from the raw responses in `data/benchmarks/raw/` (Anveet's PR #22 commits the HMRC ones, gzipped; Comtrade raw is 1.1 GB and not committed). Result: 19 rows, global plus CN-GB and AE-GB for most goods, about 100,000 HMRC OTS rows over 2023-2025, all `is_mock: false`. Sanity: copper cathode median about $10/kg, green coffee about $7/kg, laptops from China about $471/unit, M-type screws from China about $4/kg. Global bands are wide (p90/p10 up to 160x for screws, which mix commodity bolts with specialist fasteners), so route rows matter.
- **D9.2 Generator prices against the band the pipeline will use.** The generator now looks up (hs6, route) like `tbml.benchmark`, falling back to the global row, and defaults to `bands.json`. OVER_PRICE is planted at 2-300x the p90 and UNDER_PRICE at 1/2-1/30 of the p10, instead of multiples of the median: with real, wide bands "3x the median" can still be a normal price. Synthetic set regenerated (seed 42, n 60). Result: all 32 planted anomalies fire their rule; 0/36 clean and 0/6 hard negatives reach review; INV-2024-0009 (route anomaly alone, one medium flag, score 15) stays low by the scoring design.
- **D9.3 Exchange rates sourced.** `fx_annual.csv` and `fx.csv` now use the US Federal Reserve G.5A annual averages (GBP, EUR, CNY, 2022-2025) and the CBUAE AED peg. CZK is not in G.5A, stays approximate and no test invoice uses it.
- **D9.4 R8 at the floor.** Confidence equal to `min_confidence` now counts as weak (`<=`), since extraction caps unverified numbers at exactly 0.5 and they were never flagged.
- **D9.5 Screw weights.** Added M5, M8 and M12 to `unit_weights.csv` with the calculation in each row, so counted screws of those sizes can be priced.
